# Codex security review of the M2 preview API (commit 353467a, 2026-11-21)

Independent of Claude's review in 2026-11-21-m2-preview-api.md.

## Review of `353467a`

### Critical

None found. The deployed reader uses anonymous GitHub requests. I found no path to an arbitrary outbound host, disclosure of never-public bytes, or same-origin script execution.

### High

- **Repository names can change after the ID check, poisoning the pinned cache** (V4-SEC-03, V4-CACHE-05). Start a preview for public repository A, then rename or transfer A and put repository B at its former name before the next GitHub request. HEAD, tree, and raw reads use the mutable name. Import can store B’s outline under A’s ID and B’s SHA. A cold GET can also populate that key when supplied B’s SHA. Later requests for A can return B’s content until expiry. Use stable-ID-scoped reads for commit, tree, and blob retrieval. Constrain redirects to the expected operation and repository. Test a namespace swap between lookup and fetch with two repository IDs. The current fake ignores owner and name for these reads. [Import and GET binding](/home/user/lectale-m2/apps/edge_api/src/preview/routes.ts:100) · [Name-scoped reader](/home/user/lectale-m2/apps/edge_api/src/github/rest-reader.ts:101) · [Test fake](/home/user/lectale-m2/apps/edge_api/test/preview/fake-github-reader.ts:39) · [GitHub rename behavior](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)

### Medium

- **Warm imports bypass visibility and name checks** (SEC-005, V4-CACHE-02). Warm an import, then make the repository private or replace it at the same name. A new anonymous caller can get `200` with the old outline, ID, SHA, and README presence for up to 60 seconds. Previously cached GET responses can also be reused downstream for up to 300 seconds without reaching the Worker. Revalidate the name-to-ID mapping and visibility before returning an outline. If withdrawal must take effect on the next GET, require downstream revalidation while retaining internal byte caching. Test warm import after both transitions and GET through a real HTTP cache. [Import shortcut](/home/user/lectale-m2/apps/edge_api/src/preview/routes.ts:90) · [GET cache policy](/home/user/lectale-m2/apps/edge_api/src/preview/cache.ts:1)

- **Anonymous requests can exhaust GitHub’s shared rate budget** (V4-CACHE-05). Repeated GETs to one warm README each make an anonymous REST visibility lookup. Cold imports and misses add calls. An attacker can exhaust the GitHub quota for a shared egress IP and cause other readers to receive `429`. Add admission limits before outbound work, coalesce concurrent lookups, and apply a shared cooldown after throttling. Test the maximum upstream calls under parallel warm and cold traffic. The existing tests verify translation to `429`, while the warm-file test explicitly expects one lookup per GET. [Visibility lookup](/home/user/lectale-m2/apps/edge_api/src/preview/routes.ts:124) · [Warm GET test](/home/user/lectale-m2/apps/edge_api/test/preview/routes.test.ts:231) · [GitHub REST limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

- **Cold previews can exceed the Free CPU budget** (V4-COST-04, N7). A fresh commit with a large valid manifest forces synchronous YAML validation. A large repository also forces a full recursive-tree JSON parse and two entry walks before manifest validation. My local run measured **120 ms median for 2,000 resources** in validation alone. Production CPU was unmeasured. Bound metadata bytes and tree work before deserialization, then enforce a measured validation budget or move validation off the request path. Test large valid and invalid cold previews under the production limit. [Metadata parsing](/home/user/lectale-m2/apps/edge_api/src/github/rest-reader.ts:79) · [Tree indexing](/home/user/lectale-m2/apps/edge_api/src/preview/pinned.ts:67) · [Benchmark](/home/user/lectale-m2/apps/edge_api/test/contract/bench.ts:62) · [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

- **Range requests bypass cached bytes and trust the upstream interval** (V4-COST-04). Repeated open-ended or one-byte ranges each trigger a raw fetch, even with a complete cached file. The Worker accepts any syntactically valid upstream `Content-Range`, including one inconsistent with the request or known file size. Validate and normalize ranges against the pinned size, serve eligible ranges from the complete cache entry, bound transfer and concurrency, and verify the upstream interval. Add multipart, reversed, oversized, mismatched `206`, ignored Range, and warm-cache tests. [Range handling](/home/user/lectale-m2/apps/edge_api/src/preview/file.ts:54) · [Existing Range tests](/home/user/lectale-m2/apps/edge_api/test/preview/routes.test.ts:277) · [Cloudflare Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/)

### Low

- **The 404 envelope is neutral, but timing equivalence is unproven** (SEC-005). Repeated probes can distinguish local address rejection from provider-backed rejection. An upstream `403` without throttle headers reads up to 4 KiB before returning, while `404` cancels immediately. That can expose which denial path ran if GitHub returns distinct statuses. GitHub documents `404` for anonymous private-repo lookups. Test the real adapter’s private and missing paths for status, body excluding request ID, headers, and latency distributions. Normalize work where it differs by visibility. [Denial handling](/home/user/lectale-m2/apps/edge_api/src/github/rest-reader.ts:47) · [404 test](/home/user/lectale-m2/apps/edge_api/test/preview/routes.test.ts:131) · [GitHub private-resource behavior](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api)

- **Inline media relies on filename typing and a sandbox-only CSP** (SEC-014). A repository can supply HTML or SVG bytes under a raster or PDF filename. The Worker emits the extension’s MIME without checking the bytes. `nosniff` and bare `sandbox` are present. I found no browser execution path, but the file policy omits `default-src` and `frame-ancestors`. Add restrictive directives consistent with the intended viewer, validate inline formats where practical, and browser-test SVG, mislabeled markup, and hostile README content. Current tests assert headers, not browser behavior. [File headers](/home/user/lectale-m2/apps/edge_api/src/preview/file.ts:25) · [CSP middleware](/home/user/lectale-m2/apps/edge_api/src/index.ts:17) · [CSP specification](https://www.w3.org/TR/CSP3/)

### Checked and found sound

Exact HTTPS host checks cover the initial URL and every redirect. Cross-origin redirects are rejected, outbound headers are constructed locally, and mocks cover the four-fetch redirect ceiling and credential isolation. A cold import has at most 16 outbound fetches or 19 operations including its Cache API calls, within the 50-subrequest budget. Tests also cover SHA-separated entries, scoped IDs, symlink and encoded-slash rejection, HTML attachment handling, and `nosniff` on `200` and `206`. [Fetch tests](/home/user/lectale-m2/apps/edge_api/test/preview/fetch.test.ts:6) · [Route tests](/home/user/lectale-m2/apps/edge_api/test/preview/routes.test.ts:214)

I inspected the suite and ran the local CPU benchmark. Live GitHub ID lookup, deployed cache behavior, and browser execution remain unverified. No files changed.
